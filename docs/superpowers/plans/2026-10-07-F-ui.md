# Plan F — UI de cuentas, pools de llaves y puerta de calidad

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Que el usuario gestione desde la web las cuentas por CLI (crear con los comandos de login, ver uso de 5 h y 7 días, borrar), las llaves del pool de cada provider y los ajustes de verificación y revisión, y que vea en cada job sus intentos de trabajo, verificación y revisión.

**Architecture:** Componentes nuevos y chicos (`AccountsCard`, `QualityGateSettings`, `CredentialPoolPanel`) con hooks TanStack Query propios. `Agents.tsx` y `Providers.tsx` solo los montan y suman columnas. Los tipos de `types/smart.ts` y `types/provider.ts` reflejan los modelos nuevos del backend.

**Tech Stack:** React 18, TypeScript, TanStack Query, Tailwind, vitest + Testing Library.

**Spec:** `docs/superpowers/specs/2026-10-07-orquestacion-transparente-design.md` (sección 9).

**Depende de:** backend de los planes A6 (`GET /api/providers/{id}/credentials`), B4 (`/api/accounts`), D2 (campos de `JobRequest`, `DelegationConfig` y `Job`).

  it('lists slots, missing vars and never shows values', () => {
    render(<CredentialPoolPanel provider={provider} />)
    expect(screen.getByText('ANTHROPIC_API_KEY_2')).toBeInTheDocument()
    expect(screen.getByText('cooling')).toBeInTheDocument()
    expect(screen.getByText(/sin valor en .env/)).toBeInTheDocument()

    fireEvent.click(button)
    expect(add).toHaveBeenCalledWith({ value: 'sk-123' }, expect.anything())
